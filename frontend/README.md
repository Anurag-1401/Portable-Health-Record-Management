# Portable Health Record System — Frontend

React + Vite PWA, wrapped with Capacitor for Android/iOS, implementing the
client layer described in the project's architecture doc (patient app,
doctor/clinic portal, and emergency-responder quick-access mode, all from
one codebase).

## What's already wired up

- **PWA**: installable, offline app-shell via `vite-plugin-pwa` (Workbox).
  Verified with `npm run build` — see `dist/sw.js` after building.
- **Capacitor**: initialized (`capacitor.config.ts`), core + camera/network/
  preferences/push/status-bar/splash-screen plugins installed. Native
  `android/`/`ios/` folders are **not** generated yet — see step 4 below.
- **Routing + RBAC**: `react-router-dom`, with `ProtectedRoute` and
  `RoleGate` enforcing the four-tier access model (patient / doctor /
  emergency responder / government verifier) at the UI layer.
- **Offline storage**: raw IndexedDB wrapper (`src/lib/offlineDb.js`) +
  a sync queue (`src/lib/syncQueue.js`) implementing the last-write-wins
  vs. manual-flag-for-review split for critical fields.
- **Hash chain**: client-side SHA-256 chain computation/verification
  (`src/lib/hashChain.js`), matching the server-side schema.
- **Platform-adaptive QR**: `src/components/qr/QRScanner.jsx` branches on
  `Capacitor.getPlatform()` — web path fully implemented with
  `html5-qrcode`; native path stubbed with a clear TODO (needs a native
  barcode plugin + platform permission strings, see the file's header
  comment).
- **Design tokens**: Tailwind config with a deliberate color system (see
  comments in `tailwind.config.js`) — teal `trust` for primary actions,
  a reserved `emergency` color used *only* in the responder view/critical
  badges, `warmth` for success states, warm-gray `neutral` for outdoor
  readability, and `Noto Sans` + `Noto Sans Devanagari` for multi-language
  support.

Everything marked `TODO` in the code is scaffolding, not a stub error —
it's the next thing to implement, usually pointing at the specific Request
Set B item that covers it (e.g. "Request Set B, item 7" = the Record
Management API).

## 1. Install

```bash
npm install
```

## 2. Configure environment

```bash
cp .env.example .env.local
# edit .env.local — set VITE_API_BASE_URL to wherever your backend runs
```

## 3. Run in the browser (fastest loop for UI work)

```bash
npm run dev
```

Opens on `http://localhost:5173`. `server.host: true` in `vite.config.js`
also exposes it on your LAN — check the terminal output for a `Network:`
URL to open on a phone's browser without installing anything, useful for
quickly testing the mobile-web layout.

Login uses OTP — until the Auth Service (Request Set B, item 3) is live,
`authApi.requestOtp`/`verifyOtp` will fail against `VITE_API_BASE_URL`;
point them at a mock server or stub the responses while working on UI only.

## 4. Add native platforms (Android / iOS)

Native platforms are **not** generated by `npm install` — Capacitor adds
them explicitly, and once added they're real native projects that get
edited in Android Studio / Xcode, not just config files.

```bash
# Build the web app first — Capacitor copies dist/ into the native shell
npm run build

npx cap add android
npx cap add ios      # macOS + Xcode only

# Every time you change frontend code and want to see it natively:
npm run build && npx cap sync
```

Then open the native project to build/run on a device or emulator:

```bash
npx cap open android   # opens Android Studio
npx cap open ios       # opens Xcode (macOS only)
```

**Before your first native build**, you'll need to add camera permission
strings, since `@capacitor/camera` and any barcode-scanning plugin you add
require them or the app will crash on permission request:
- Android: `android/app/src/main/AndroidManifest.xml` → add
  `<uses-permission android:name="android.permission.CAMERA" />`
- iOS: `ios/App/App/Info.plist` → add `NSCameraUsageDescription` with a
  user-facing explanation string (e.g. "Used to scan patient Health ID QR
  codes.")

## 5. Production build (web)

```bash
npm run build    # outputs to dist/
npm run preview  # serve the production build locally to sanity-check it
```

## Offline architecture (what's implemented vs. what's next)

| Layer | Status | Where |
|---|---|---|
| App shell precaching (works with zero network) | done | `vite.config.js` VitePWA `workbox.globPatterns` |
| GET record reads — NetworkFirst w/ cache fallback | done | `vite.config.js` `runtimeCaching` |
| Local writes queued while offline | scaffolded | `src/lib/syncQueue.js` `queueWrite()` |
| Auto-sync on reconnect | scaffolded | `src/hooks/useNetworkStatus.js` calls `processSyncQueue()` |
| Conflict resolution (last-write-wins vs. manual-flag) | scaffolded, needs backend pairing | `src/lib/syncQueue.js` `CRITICAL_FIELDS` |
| Actual record CRUD against a real backend | not yet | needs Request Set B item 7 (API endpoints) first |

## Folder structure

```
src/
  features/            one folder per role-facing feature area
    auth/               pages, context, API calls for login/OTP
    patient/            dashboard, records list
    doctor/              dashboard, QR scan + consent request
    emergency/            no-consent critical-info access
    government/            eligibility-only lookup
  components/
    layout/             AppShell, Navbar, RoleGate (RBAC UI boundary)
    ui/                 Button, Card, Badge, LoadingSpinner
    qr/                 QRScanner (platform-adaptive), QRDisplay
  lib/                  platform.js, offlineDb.js, syncQueue.js,
                         hashChain.js, apiClient.js — the non-UI core
  hooks/                useAuth, useNetworkStatus
  constants/            accessLevels.js, fhirResourceTypes.js — mirror
                         the Postgres enums, keep in sync with schema.sql
  routes/               route table + ProtectedRoute
  styles/               Tailwind entrypoint
```

Why feature-based rather than type-based (`pages/`, `components/` for
everything): each role (patient/doctor/responder/verifier) is a fairly
separate user journey with its own screens and logic. Grouping by feature
means you can work on "the emergency responder flow" as one folder instead
of hunting across five type-based folders every time.

## Known rough edges (intentional, for now)

- `npm audit` reports a few moderate/high advisories — these are in Vite's
  dev-server dependency chain (a longstanding, low-real-world-risk class of
  advisory for local dev servers), not in anything shipped to production.
  Worth a one-line mention in your report's "limitations" section rather
  than something to chase down before the deadline.
- The main JS bundle is ~640 KB pre-gzip, which Vite warns about. Fine for
  a college-project prototype; if you want to address it later, the
  cheapest win is route-based `React.lazy()` code-splitting per feature
  folder (patient/doctor/emergency bundles only load when that role logs
  in) — not necessary to do now.
